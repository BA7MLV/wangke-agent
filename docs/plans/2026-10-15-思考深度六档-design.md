# 思考深度改 6 档（第一档「不思考」）+ 档位映射对齐业界刻度

- 状态：**已实现并验证**（验证记录见 §4；同日按用户反馈又改了一版版式，见 §5）
- 日期：2026-10-15
- 需求（用户原话）：「思考深度这里设置 6 档，第一档是不思考。除非非思考模型，不然调整为
  对应的映射这一块对齐业界最佳实践。」

## 0. 一句话方案

把 `ReasoningEffort` 从自造的 3 档（low / high / max）换成**业界通行的 6 档刻度**
（none / minimal / low / medium / high / xhigh，取自 OpenAI 的 `reasoning_effort`），
**第一档 `none` 就是「不思考」**；有深度档位的模型上，这条滑块**取代**原来那枚独立的
「思考」开关（关掉思考 = 拖到最左）；每档仍然**只发模型自己声明支持的参数**。

## 2. 关键决策

### 2.1 6 档取 OpenAI 那一套，不是自己再编一套

「业界最佳实践」这件事有现成答案：OpenAI 把 `reasoning_effort` 从 4 档
（minimal / low / medium / high）扩成了 **none / minimal / low / medium / high / xhigh 六档**，
`none` 就是「无推理」。这正好是用户描述的形状 —— 6 档、第一档是不思考。

选它而不是继续自造名字的另一个理由：**它是一条能装下各家的刻度**。
Anthropic 用 budget 阶梯（1k/2k/4k/8k/16k/32k），Kimi / GLM 用 low/high/max ——
前者能按比例折算到刻度上，后者能按次序映射（见 §2.4）。自造一套的话，
每接一家都要重新论证一次映射。

### 2.2 「不思考」发 `enable_thinking: false`，不发 `reasoning_effort: 'none'`

两者看着等价，实际不等价：硅基流动文档里 `reasoning_effort` 的 enum **只有 `high` / `max`**
（原文还写着「low 与 medium 会映射为 high」），压根没有 `none`。发 `'none'` 会被拒或静默忽略。

所以**「关掉思考」和「思考多深」是两个字段**，`none` 因此不放进 `ReasoningEffort`：

- `ReasoningEffort` = 5 档深度（进 `reasoning_effort` / `thinking_budget`）
- `ThinkingLevel` = `'none' | ReasoningEffort` = 滑块上的 6 档（`'none'` 进 `enable_thinking: false`）

这条分支在 `thinkingParams` 里**排在查模型声明之前**：混合思考模型（Qwen3 系）默认可能是
开着的，而「关掉」不该依赖模型是否声明了档位 —— 什么都不发等于没关掉。

顺带修掉一个既有缺口：以前「关着思考」是**不传参数**（`thinkingEffort: undefined`），
现在明确传 `'none'`。`undefined` 保留给「这个模型压根不能思考」，两者语义不再混淆。

### 2.3 有深度档位的模型，滑块取代开关

改之前一个模型上同时存在两枚控件：Switch（思考开 / 关）+ 滑块（低 / 高 / 最大），
而且滑块还**只在开关打开时才渲染**。两处都能表达「关」之后就会互相打架 ——
开关关着、滑块停在「高」，用户没法判断下一次提问到底思考还是不思考。

现在的规则（两处界面同一套）：

| 模型能力 | 给什么 |
|---|---|
| 能思考 + 声明了 effort 档位或 budget 区间 | 一条 6 档滑块，**第一档就是不思考** |
| 能思考但只有开关（Qwen3.5 系、部分 DeepSeek） | 一枚灯泡 / Switch（它没有深度可调） |
| 不会思考 | 什么都不给 |

配套的两条约束：滑块**不跟着 `thinking` 隐藏**（第一档就是关，藏起来用户就没法把思考关回去）；
播放页问答工具行里的灯泡因此只在「没有深度档位」的模型上出现，否则同一排里又是两个入口。

### 2.4 最高档必须够得着 `max`

映射规则沿用「**取不超过目标的最强档**」（保守：宁可给弱一档，也不越过用户的指令）。
但把刻度换成 OpenAI 那一套之后，我们的最高档叫 `xhigh`，而 GLM / DeepSeek 声明的是 `max` ——
按名字比大小，`xhigh` 比 `max` 弱，于是最高档会退成 `high`：**用户把滑块拉到最右却拿不到最强档**。

解法是把 `xhigh` 与 `max` 在次序上**并列最高**（两家对「最高」的叫法不同，不是两档）。
硅基流动文档原文也写着「xhigh 映射为 max」，与这条规则一致。

### 2.5 只声明 2 档的模型上，中间几档会塌到同一档 —— 这是要的

GLM-5.2 只声明 `high` / `max`，6 档滑块映射过去就是：极简 / 低 / 中 / 高 都发 `high`，
极高发 `max`。用户确认的口径是「**固定留档，映射对应的参数**」——刻度固定显示 6 档，
每档映射到模型对应的参数，**不做置灰 / 隐藏**。

理由：塌缩是模型真没有那么多档，不是控件坏了；固定 6 档刻度至少让「这台模型能到多深」
在视觉上有参照物。代价是「拖了没变化」会被读成失灵 —— 见 §6。

### 2.6 budget 折算改成逐级对半

旧的 3 档是 `low=1/4`、`high=1/2`、`max=1`。5 档深度再往中间插，均匀切分会让
「极简」和「低」的差别小到看不出来。改成**逐级对半**（1/16 → 1/8 → 1/4 → 1/2 → 1）：
思考预算的代价本来就是对数量级敏感的（Anthropic 给的推荐阶梯就是一路翻倍），
顶档仍固定拉满声明上限。

代价是**同名字义整体下移一档**（旧的 `low`=1/4，现在是 1/8）。刻度从 3 档变 6 档只能整体重排，
不能只往两头加。方向是「更省」，不会撞上限。

### 2.7 旧值 `max` 必须在三条入库路径上都收敛

`max` 这个名字现在不合法了，而它可能从三个地方进来：**localStorage 里的旧设置**、
**旧版本导出的迁移包**、将来的同步载荷。放任它进 store 的后果不是「显示不对」那么轻：
预算型模型的折算会算出 `NaN`，`JSON.stringify` 把它变成 `null` 发出去，
网关回一句跟界面现象毫无关系的 400。

三处收口：

1. `normalizeThinkingEffort`（`modelCaps.ts`）—— 规则只有一份：`max → xhigh`，
   认不出来的返回 null（= 当没设过），`'none'` 也返回 null（它不属于这个字段）。
2. `store.update()` —— **所有**写入路径（界面 / 迁移包导入 / 将来的同步）都过这里，
   在这一处收敛，不用每个调用方各修一遍；认不出来的名字整条丢掉，不留在 store 里
   （留着会让滑块 `findIndex` 返回 -1、静默停在第 0 格，而发出去的仍是那个不存在的名字）。
3. `migrateSettings` + 持久化 `version: 2 → 3` —— **hydrate 不经过 `update`**，
   而 persist 只在版本号对不上时才走 migrate，版本号不动的话老用户的 `'max'` 会原样读进来。

`thinkingParams` 里另加一道兜底：算不出预算比例就退到「只发 `enable_thinking`」，
不让 `NaN` 有机会混进请求体。

## 3. 结构

```
THINKING_LEVELS（modelCaps，6 档：值 + 文案）
   ├ ReasoningEffortSlider        ← 只负责画，档位表不在这里
   ├ ModelPicker（对话页 chip 面板）  ← canDepth ? 滑块 : Switch
   └ ChatPanel（播放页问答工具行）    ← canDepth ? 滑块 : 灯泡

settings.thinkingEffort(5 档) + settings.thinkingEnabled(bool)
   └ ThinkingLevel = thinkingEnabled ? thinkingEffort : 'none'
        └ thinkingParams(catalogId, model, level)
             ├ 'none'            → { enable_thinking: false }
             ├ 声明 effort 档位   → { enable_thinking: true, reasoning_effort: 映射后的档位名 }
             ├ 声明 budget 区间   → { enable_thinking: true, thinking_budget: 上限 × 比例 }
             └ 只有开关 / 无元数据 → { enable_thinking: true }
```

**为什么 off 不落进 `thinkingEffort`**：`thinkingEffort` 存的是「深度」，off 是另一件事，
由已有的 `thinkingEnabled` 表达（它也服务只有开关的模型）。这样既没有第二份真相，
也不用改落库结构 —— 旧值 `low` / `high` 在新刻度里仍然合法。

## 5. 同日修订：这一块的版式（用户看完成品后的反馈）

用户原话：「这里的样式太丑了 优化下这里的样式，思考 先推演再作答。更准，也更慢更贵。
这个文本去掉。」

丑在两件事上，都不是随手调数字能解决的：

### 5.1 同一个东西被起了两次名字

上一版把「思考」那一行拆成了三段：`思考`（标题）+ `先推演再作答。更准，也更慢更贵。`
（说明）+ 下面再来一行 `思考深度` + 滑块。**而 §2.3 又把开关从标题行拿掉了** ——
于是标题行只剩一个孤儿「思考」，中间那句是承诺不是信息（「更准更慢更贵」用户自己会判断），
真正在调的东西却在第三行。

现在收成**一条**设置行：标签贴左、控件占右，没有第二行说明。只有开关的模型（没有滑块）
才补一句 `这个模型只有开关，没有深度档位。`—— 它解释的是一个**缺失**，
挂在行下方、小一号、同样弱化，不与标签抢视线。

### 5.2 滑块本身是「2010 年代 range input」的观感

面板里其它东西都是克制的（细边框、小圆角、弱化的次要文字），唯独这条滑块：
10px 粗轨道 + 蓝填充 + 20px 白球配灰边与两层阴影。它比模型列表还抢眼。

改法：轨道 10px → **6px**，thumb 20px → **16px** 并把灰边换成**主色环**、只留一层浅影；
刻度圆点 5px → 4px，并按 `data-filled` 分两种颜色（填充侧白点、未填充侧灰点）——
原来是清一色灰点，压在蓝填充上直接看不见。顺带删掉 `data-active`：那颗点正好被 thumb
盖住，标了也看不见，属于「看着像功能其实没用」。

### 5.3 顺手挖出两个真 bug（都不是这次引入的）

用临时探针（Playwright，不入库）把这一行按 3 倍分辨率截出来、并逐像素量了 thumb 的
命中范围之后，两个都藏不住了：

1. **thumb 被裁成半圆**。`.reasoning-slider__track` 上有 `overflow: hidden`，而 range input
   就挂在这个容器里、thumb 又比轨道高 —— 一裁就是一颗被切平的球。
   填充区的圆角本来就是它自己 `border-radius` 画的，这个 `overflow` 纯属多余。
   （10px 轨道 + 20px thumb 时已经能看出来，只是没人盯。）
2. **input 被行盒顶下去 9px**。input 是行内级元素，塞在普通块容器里会落进行盒、
   被基线顶到轨道下方（实测：轨道 top 788，input top 797），thumb 于是整颗挂在轨道下沿。
   把轨道改成 `display: flex` 之后 input 变成块级 flex 项，两者 top 一致，
   thumb 相对轨道中心的偏移从 +9px 变成 **0**。

两条都写进了 CSS 注释（就在 `.reasoning-slider__track` 上），因为这个容器的写法看着
「随便改改就行」，实际改坏一次就是半圆或挂偏。

## 6. 已知未做 / 风险

- **页面链路仍无回归**。改的是 UI（滑块档位数、控件去留），但唯一能自动跑的还是纯逻辑单测；
  要页面级覆盖得先有「真实 models.dev 元数据 + 可用 key + 已收藏的深度模型」这套前置，
  和上一版一样没做。人工核对过两处界面的条件分支（`canDepth` 的三态）。
- **播放页工具行变宽了约 45px**（滑块 + 档位文案比原来的三个文字按钮宽，标签 `思考深度`
  保留在桌面档）。那一行是 `PanelBar wrap={false}`，宽度不够时会横向溢出而不是换行 ——
  这次没做版式探针，只是把同排那枚灯泡在「有深度档位」时去掉了，把多出来的宽度抵掉一部分。
- **塌缩档位会被读成失灵**（§2.5）。用户选了「固定留档」，所以没做置灰 / 吸附；
  若之后觉得误导，正确的改法是「刻度仍 6 档、够不到的档位不可停靠」，
  而不是把刻度改成随模型变。
- **`enable_thinking: false` 是否被所有网关认**：对声明了 effort 档位却没声明开关的模型
  （如 GLM-5.2），这个字段是**我们替它发的**。既有代码本来就一直在替这类模型发
  `enable_thinking: true`，所以不是本次新引入的风险；但若网关忽略它，最左那档会静默
  退化成「按模型默认」。要确认得拿真 key 打一次。
- **播放页那条滑块的禁用状态没跟着变**：原先的按钮组在生成中也是可点的（同排灯泡反被
  禁用），本次只换控件、不动这条既有行为，保持「不顺手改别人没让我改的东西」。
