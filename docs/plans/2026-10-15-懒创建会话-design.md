# 懒创建会话（草稿态）设计

日期：2026-10-15
状态：**已落地**（`store/courseChat.ts` / `pages/CourseChat.tsx` + `scripts/test-lazy-session.mjs` / `scripts/e2e-lazy-session.mjs`）
二轮（同日）：**「新建会话」的入口补回来了** —— 落在侧栏首项（原「AI 助手」→「新会话」，且该格不再有选中态），见 §七；实测记录见 §八。

## 背景与目标

侧栏 Recent 里会出现**空壳会话**：标题是「新会话」、点进去一个字都没有。

它们不是功能，是**一条不变量的副产品**。「`activeId` 永远非空」这条不变量此前靠三处 `newSessionRow()` 兜底维持：

| 位置 | 什么时候落库 | 为什么要兜 |
| --- | --- | --- |
| `bootstrap()` | 库里一条未归档会话都没有 | 否则对话页没有落脚的会话，`send()` 直接被 `activeId == null` 挡掉 |
| `deleteSessionById()` | 删到一条不剩 | 同上 |
| `setArchived()` | 归档到一条不剩 | 同上（这条是上一轮 `e2e-recent-menu` 揪出来的 bug 的修法） |
| `createSession()` | **无条件** | 用户点了「新建」 |

后果：连点两次「新建」留下两条「新会话」；建了一条什么都没问就切走，那条永远留着；归档掉唯一那条会当场再造一条空壳。

目标：**库里只存「写过消息的会话」**，空会话这个概念在数据层不存在。

## 一、方案：懒创建（草稿态）

把「会话」拆成两个状态：

| 状态 | `activeId` | 库里有没有行 | 出现在 Recent |
| --- | --- | --- | --- |
| **草稿态**（用户面前那个「还没开始的会话」） | `null` | 没有 | 不出现 |
| **已落库** | `number` | 有 | 出现 |

落库时机**只有一处**：`send()` 里发现 `activeId == null`，也就是用户真的发出了第一条消息。

于是「空会话」在数据层不存在 —— 不是靠「新建之前先看看有没有空的」那种判据绕开，而是**根本没有产生它的路径**。

### 为什么不做「空会话复用」那条轻量方案

那是我最初的提议（`createSession` 里判断当前会话是不是空的，空就复用）。它能挡住连点，但**挡不住「建了不用又切回去」**：A 有内容 → 新建出空 B → 点 Recent 回 A → 再点新建出空 C，B 和 C 都留下了。因为判据只看「当前」那条，管不到「别的」空会话。要补就得再加一条「bootstrap 时回收多余空会话」的清理规则 —— 而那条规则会连用户**改过名的空会话**一起回收掉，于是又得引一个「标题是不是默认值」的判据。三条规则叠起来，比懒创建这一条还复杂。

## 二、不变量（改前 → 改后）

改前：

- **I1** `activeId != null` 恒成立
- **I2** `sessions` 至少一条

改后：

- **I1′** `activeId === null` ⇔ 草稿态，且**只有它**表示草稿态
- **I2′** `sessions` 可以为空（全新用户、或全部归档之后）
- **I3**（新）**库里的会话一定有消息** —— 这是「Recent 里没有空壳」的形式化，也是本轮要守的东西

I1 是承重的：`send` / `loadSession` / `answerAsk` / 页面 effect 都拿 `activeId != null` 当判据。所以这次改动的**全部风险**都集中在「哪些判据要跟着改」上 —— 见 §三。

## 三、判据清单（逐条交代）

| 位置 | 改前 | 改后 | 为什么 |
| --- | --- | --- | --- |
| `send()` 入口 | `activeId == null` 直接 return | 允许为 null，**在函数里落库** | 这正是懒创建的那一处 |
| `send()` 的 `sessionId` | `state.activeId`（已保证非空） | `let`，null 时先建行 | 落库后所有下游（`db.chats.add`、标题、上下文回写）用的是同一个 `let` |
| `sessionReady`（页面） | `activeId != null && loaded` | `loaded` | 草稿态**可以发消息**，否则草稿态是个死状态 |
| `loaded` 语义 | 「本会话消息已从库里读完」 | 「当前视图的消息已就绪」 | 草稿态没有东西要读，所以它天然就绪（`bootstrap` 在无会话时直接置 `true`）。不这么改，草稿态的输入框会永久禁用 |
| `answerAsk()` | `activeId == null` return | **不动** | 提问卡只可能由 agent 循环产生，而循环只可能由 `send` 之后发生 —— 那时 `activeId` 必然非空。这条判据从「防呆」降级成「断言」，留着无害 |
| `loadSession()` | 不变 | 不变 | 它只在有 id 时被调用 |
| `setSkillIds()` / `clearCourseContext()` | `id == null` 时 return（静默丢弃） | 草稿态**只写内存**，落库时随行一起写 | 静默丢弃 = 用户点了技能范围、界面看着生效了、发第一条消息时没了 |
| `bootstrap()` | 没有会话就建一条 | 不建，`activeId` 留 `null` | I2′ |
| `deleteSessionById()` | 删到不剩 → 建一条 | 删到不剩 → `toDraft()` | I3 |
| `setArchived()` | 归档到不剩 → 建一条 | 同上 | I3 |
| `createSession()` | 无条件建行 | 切到草稿态（已经是草稿态就什么都不做） | I3；顺带「空会话不新建」这条规则变成了**免费**的 —— 草稿态天然可复用，不需要判据 |

### 落库顺序：先落库，再塞消息

```ts
let sessionId = state.activeId;
if (sessionId == null) {
  try {
    const row = await newSessionRow();
    sessionId = row.id!;
    set((s) => ({ sessions: [...s.sessions, row], activeId: sessionId }));
  } catch (error) {
    // 视图里只加一条报错消息，**草稿原样留在输入框**
    return;
  }
}
```

反过来的顺序（先乐观 `set` 用户消息、再落库）在落库失败时会留下「一条提问 + 一条报错」却没有对应会话行 —— 刷新后整段消失，而用户以为自己问过了。**这类「看着问过了其实没有」正是本轮最该避免的失效方式。**

## 四、口径（四个需要拍板的点）

1. **草稿态时 Recent 没有高亮项。** 那条会话确实还不存在，Recent 是「历史记录」不是「当前状态」。ChatGPT 的新对话期间侧栏同样没有选中项。
2. **草稿态时顶栏标题显示「新会话」**，不是「AI 助手」。「AI 助手」是**页面**的名字，「新会话」是**这条会话**的名字 —— 顶栏标题这一栏回答的是后者。
3. **草稿态设置的技能范围 / 课程上下文只活在内存里**，随首条消息一起落库；切走即丢。草稿态本来就没有持久化承诺，为它落库等于又把空会话造回来了。
4. **落库后立刻关掉浏览器**会留下「只有一条用户消息、没有回答」的会话。它**有内容**，不属于空壳，保留 —— 用户回来能看见自己问过什么，比整段消失好。

### 为什么单测能打在 store 上，而不是退化成纯函数测试

本轮改的**全是 store 的生命周期**（什么时候落库、删完落到哪），把它抽成纯函数再测，测的就不是真实那条路径了。`fake-indexeddb` + esbuild 打 bundle 能让 store 本体在 Node 里真跑（`test-migration.mjs` / `test-agent-loop.mjs` 同一套做法），所以单测直接调 `useCourseChat.getState().send(...)`，断言**库里的行数**。假模型流用替换 `globalThis.fetch` 的 SSE 发生器（`test-agent-loop.mjs` 的写法）。

分工：单测守**数据层的不变量**（I3），e2e 守**页面链路**（点删除按钮 → 回到草稿态、刷新 → 不产生空壳），两者不重叠。

## 七、二轮：「新建会话」入口落在侧栏首项（「AI 助手」→「新会话」）

§六.2 把「放哪儿」留给用户拍板。二轮拍的是**导航项「AI 助手」本身**，并附带一条删除：**去掉这一格的选中态**。

### 7.1 改了什么

| 位置 | 改前 | 改后 |
| --- | --- | --- |
| `components/appNav.tsx` 首项 | `label: 'AI 助手'`、`onClick: () => navigate('/')` | `label: '新会话'`、`isAction: true`、`onClick: () => { createSession(); navigate('/') }` |
| `ui/layout.tsx` 的 `NavItem` | 只有「目的地」一种项 | 新增 `isAction?: boolean`（动作项） |
| `ui/layout.tsx` 导航 `ListBox` | `selectedKeys={[rail.value]}` | `rail.items.filter((it) => !it.isAction && it.value === rail.value).map(...)` |

标题栏的兜底仍是 §四.2 定的那套：草稿态显示「新会话」。「新会话」现在是**会话名**，出现在两处口径一致的地方 —— 顶栏标题与侧栏首项。

### 7.2 为什么它必须没有选中态

高亮的含义是「你现在在哪」。改造之前这一格代表**页面**（AI 助手），导航栏拿它回答「你在哪」是成立的；
改成**动作**（新会话）之后这句话就落空了 —— 一个动作不是一个地方，而草稿态下更不存在「正在看的某条会话」
（§四.1 已经定了草稿态 Recent 不高亮）。

于是侧栏里回答「你在哪」的只剩两处：其余导航项（课程库 / 学习）与 Recent 里那条当前会话。

⚠️ 实现上**不是「把选中样式删掉」**：只删样式的话 `aria-selected` 还是 `true`，读屏用户照样听得出
「导航栏选中了它」，而且点一下之后它会真的亮起来。要做的是让它**根本不进 `selectedKeys`** ——
底色、文字色、`aria-selected` 三者由同一个来源驱动，跳过这一环它们一起不成立。

⚠️ 另一个容易误改的点：`value: 'chat'` **留着没动**。它现在不参与选中（动作项被过滤掉了），
只是 React key 与 e2e / 探针的选择器锚点。`CourseChat` 仍然传 `useAppNav('chat')` ——
传什么都不点亮任何一格，这正是首页该有的样子。

### 7.3 点一下发生什么：`createSession()` + `navigate('/')`

两件事缺一不可：

- 只 `navigate('/')`：人在会话 X 里点它**毫无反应**（已经位于 `/`，`navigate` 是空操作）——
  改造之前首项就是这个毛病，它当时只是「回到对话页」；
- 只 `createSession()`：在课程库 / 学习页点它切不回来。

两个副作用说清楚：

1. **生成中**：`createSession` 自己会拒绝（与其它切会话入口同一口径），此时只有跳转生效。
   没有给这一格做禁用态 —— 导航栏是全应用共用的一份，为「对话正在生成」把它变灰，
   等于在课程库页也灰掉一个无关的动作。
2. **连点**：草稿态下 `createSession` 幂等（`activeId == null` 直接返回），所以连点攒不出空壳。
   这一条是懒创建白送的：§三 里那条「新建会话 → 切草稿态」的规则在这里同时承担了
   「空会话不新建」，不需要额外判据。

### 7.4 `e2e-chat-sources` §4 那条用例的下落

顶栏「新建对话」被删时，`e2e-chat-sources` 留过一条注记：那条「点一下真的新建并切过去、消息区回到空态」
的用例**没有替代物**，「等入口在别处恢复时，把这段搬过去，别只补渲染断言」。

入口现在回来了，等价用例落在 `e2e-lazy-session` §6：有会话在手上 → 点「新会话」→ 回到草稿态
（标题「新会话」、消息区空态、Recent 无选中项）**且库里行数不变**。注意它断言的是
「**一条都没多**」，而不是原来那句「多了一条」—— 同一个动作，懒创建之后口径反了。
`e2e-chat-sources` 里那段注记改成了指向这里，不重复实现。

### 7.5 没做的事

- **图标没换**（仍是「聊天」的双气泡，不是加号 / 铅笔）：这一格的去处还是对话页，
  新会话只是它默认落到的那条会话。要换成 `add` / `edit` 是一行的事，但那是视觉决定，没替用户做主。
- **没把这一格从导航 `ListBox` 里搬出去变成独立按钮**：语义上「动作躺在单选列表里」确实别扭，
  但搬出去要另起一套键盘与视觉，而它现在跟另外两格共用同一套 pill / hover / 上下键。
  真要搬，`isAction` 这个标记就是现成的抓手。
- **播放页 `ChatPanel` 的「新开会话」不动**（同 §六.1）。

### 8.2 页面链路（`e2e-lazy-session.mjs`，生产构建 + 页内假模型流）

```
✅ 全新库进对话页 = 草稿态：库里 0 行、Recent 整组不渲染
✅ 草稿态顶栏标题是「新会话」而不是页面名「AI 助手」
✅ 草稿态的消息区是空态，输入框与发送键可用（不是死状态）
✅ 发第一条消息：这时才落库（1 行），标题 = 首条消息截断
✅ 落库之后：Recent 出现该行且只有它被选中，顶栏标题跟着变
✅ 刷新：仍然只有 1 行（bootstrap 不再补空会话）
✅ 删掉唯一会话：回到草稿态 —— 库里 0 行、Recent 消失、标题回「新会话」
✅ 草稿态再发一条：又落 1 行（草稿态可复用，不是死状态）
✅ 「新会话」是动作项：看着会话时它自己不高亮，Recent 才是「你在哪」的出口
✅ 点「新会话」：回到草稿态 —— 标题回「新会话」、消息区空态、Recent 无选中项、库里不新增行
✅ 草稿态连点「新会话」是幂等的：库里仍是那些行（攒不出空壳）

全部通过
```

后三条是本轮新增（§七）。它们量的是**库里的行数**与 `aria-selected`，不是截图。

### 8.3 「选中态真的没了」——按计算样式量，不按肉眼

同一份构建，1440×900，浅色主题，读 `[data-testid^="nav-rail"]` 的 `aria-selected` 与 `background-color`：

| 页面 | 项 | aria-selected | background-color |
| --- | --- | --- | --- |
| `/` | 新会话 | `false` | `rgba(0, 0, 0, 0)`（透明） |
| `/` | 课程库 | `false` | `rgba(0, 0, 0, 0)`（透明） |
| `/library` | 课程库 | `true` | `oklab(0.6204 -0.0543 -0.1873 / 0.15)`（accent-soft 药丸） |
| `/library` | 新会话 | `false` | `rgba(0, 0, 0, 0)`（透明） |

即：**目的地照旧高亮、动作项在任何页面都是透明的**。为什么不能只删样式类：那样 `aria-selected` 还会是 `true`
（见 §7.2），所以这里两条一起量。

```
✓ 三路由 × 三视口 × 明暗：标题层级、导航可达、不溢出、skip-link 全部成立
```

即：除首页外每格仍是「侧栏当前项 `aria-selected=true`」，首页那格改成断言「动作项 `!== 'true'`」；
窄屏抽屉里点 / 键盘 Enter 首项仍能跳转并自动收起（那条用例原本就点 `nav-rail-chat`，
改造之后它顺手也覆盖了「动作项在抽屉里同样能用」）。

### 8.5 全量一键跑分

**本轮未在安静的工作区执行**，记录原因以免被当成「已经全绿」：

起跑后（`node scripts/e2e-all.mjs`，无 key 档）发现同一时间仓库里有另一路构建 / 跑分在动 ——
`dist-skel` / `dist-e2e` 是 23:09 新建的、`scripts/e2e-all.mjs` 在 23:11:30 被改过、
23:18 那份 `scripts/.cache/e2e-report.md` 是**另一套脚本**写的（20 个结果，其中
`e2e-materials` / `e2e-library` / `e2e-study` / `e2e-course-chat-cards` 失败）。

两路同时跑会共用 4173 / 5173 两个端口、并且**互相覆盖同一份报告文件**，
结论既不可信、又会污染对方那一份，所以主动停掉了本路全量，改为上面的定向验证。
工作区安静后单独跑一次，把汇总回填到这里即可。

### 8.6 构建

`npm run build` = `tsc -b && vite build`：类型检查通过、5998 个模块打包通过。

⚠️ 一个环境上的坑（不是本轮引入的）：`vite build` 收尾会 `rmSync` 清空 `dist/assets`（159 个文件），
而宿主对「一次删 >50 个文件」有批量删除保护，于是构建**在最后一步报错、dist 不更新**。
本轮的做法是先把旧 `dist` 整体移出（`mv`，不删除）再构建 —— 新产物写进空目录，避开删除。
移走的旧产物在 `/tmp/wangke-dist-prev-230852/`。要做其他构建验证时记得这一条，
否则会得到「tsc 过了、包也打了，dist 却是旧的」这种最难排查的状态。
