# 输入卡上下文用量环设计

日期：2026-10-16
状态：**已落地**（`components/ContextUsageButton.tsx` + `components/context-usage.css` / `pages/CourseChat.tsx` + `pages/course-chat.css`）

## 背景与目标

对话页（课程助手）的输入卡工具行过去右端是这样：

```
[模型 chip] [技能] [排队/插入]        [🗑 删除会话] [↑ 发送]
```

用户的两点诉求：

1. **想随时看到「当前上下文用了多少」** —— 助手历史越滚越长，用户需要一个「快满了」的信号，好决定是不是该开新话题。
2. **那颗删除键的位置该让出来** —— 删除会话在侧栏 Recent 的行尾菜单里本来就有（重命名 / 置顶 / 分支 / 归档 / 删除），输入卡里再放一颗**同一件事的第二个入口**，还偏偏紧挨着发送键。

目标：把工具行最右那颗删除键换成**一枚只读的上下文用量环**，删除能力一点不丢（仍在侧栏）。

## 一、方案：环形进度 + 悬停提示

环的填充比例 = 本轮输入估算 / 上下文窗口，颜色分三档，精确数字悬停才报。

| 档位 | 阈值 | 颜色令牌 | tooltip |
| --- | --- | --- | --- |
| 正常 | ≤ 70% | `--muted` | `上下文用量 ≈32.5k / 128k（25%）` |
| 注意 | > 70% | `--warning` | 同上 |
| 危险 | > 90% | `--danger` | 上面再加「· 建议开启新话题」 |

### 为什么是环而不是常驻文字

工具行的宽度是稀缺资源（模型 chip / 技能 / 发送键都在抢）。常驻的 `≈32.5k / 128k`
会把这一行顶到换行。环把「还剩多少」压进一颗图标大小：抬眼一看比例就够，
需要精确数字的人自然会悬停。

### 为什么是 Button 而不是裸元素

HeroUI 的 `Tooltip.Trigger` 固定渲染一层 `role="button"`、`tabindex=0` 的包装元素
（`components/ContextUsageButton.tsx` 注释有实测记录）。孩子用可按键的 `Button`
才与这层包装的语义相符，也和全站 `iconButton` 的写法一致。它**刻意不挂 `onPress`**
—— 只读控件按下去不该发生任何事。

## 二、用量口径（与 `store/courseChat` 的 `send` 对齐）

估算是「系统提示词 + 历史 + 当前草稿」，与真正发出去的东西同一个口子：

| 部分 | 来源 |
| --- | --- |
| 系统提示词 | `libraryAssistantSystemPrompt(skillBlock, contextCourses, hasCourses)` |
| 技能清单 | `loadSessionSkillMeta(skillIds)` → `skillMetaBlock`（异步读库，进 state） |
| 历史 | 每条消息的 `content`（reasoning / 工具回执不随下一轮重发） |
| 草稿 | 输入框当前内容 |

`estimateTokens` 本来就是量级估值，环回答的是「快满了没有」，不是可审计的账。
阈值与**视频问答面板**底部那行用量文字（`chat-ctx--warn` / `chat-ctx--bad`）
用同一组数字与同一组语义令牌 —— 两处告警各说各话，用户会以为其中一个在骗人。

## 三、删除会话的去处

输入卡里的 `onDeleteSession` 与对应按钮一并移除，删除只剩两个入口（都在侧栏 Recent）：

- 每行行尾「更多」菜单里的**删除**；
- 键盘 `Delete` / `Backspace`（行尾按钮 Tab 走不到，靠 `onDelete` 兜底）。

两处都走同一个确认框。删掉输入卡那颗键之后，工具行里**再没有破坏性动作**，
把只读的用量环放到最右端才不需要担心误触。

## 四、验证

用一次性探针（种入不同体量的历史后截图，验完即删）实测三档：

```
normal → ≈3.7k / 131.1k（3%）   data-level = normal
warn   → ≈112.9k / 131.1k（86%） data-level = warn
bad    → ≈140.9k / 131.1k（107%）data-level = bad
```

tooltip 经无头浏览器确认读到 `上下文用量 ≈875 / 131.1k（1%）`；明暗两套主题、
1440 / 390 两档宽度下均无溢出、无运行时错误。
