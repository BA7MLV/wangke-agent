# 生成期间的会话切换：把「一轮」绑到会话上

## 背景与目标

这一版之前，生成期间**会话是硬禁的**：

- `store/courseChat.ts` 的 `loadSession` / `createSession` / `setArchived` 一进门就是
  `if (get().loading) return`；
- `pages/CourseChat.tsx` 的 Recent 那一行 `onClick` 再判一次 `!loading`，
  行尾的 分支 / 归档 / 删除 也一起 `isDisabled: loading`。

用户点了 Recent 里另一条会话**没反应**，于是「等它答，我先去看/去问另一条」这条路走不通。
实测三种场景里，这一条是唯一被硬禁的（对话页切页面、播放页切页面都还能切）。

目标：**生成期间可以自由切会话**，并且

1. 切走的那一轮**在后台继续跑**，答完照常落库；
2. 切回来能看到**还在流式的回答**，不是一句没头没尾的用户提问；
3. 切到另一条会话后**可以照常提问** —— 两条会话各自流式，互不打断（真并发）；
4. 每条会话自己的**队列 / 提问卡 / 停止键**互不串：在 A 排的队不会跑到 B 去。

## 一、根因

状态里有一组**单例**：

| 字段 | 现在的位置 | 为什么挡不住并发 |
|---|---|---|
| `messages` | store 顶层一条数组 | 切会话就整条换掉，正在流的那条不在库里，于是丢 |
| `loading` | store 顶层布尔 | 只有一个全局「正在生成」，切到 B 后 A 的流仍写着 B 的视图 |
| `queued` | store 顶层数组 | 队列没有归属，切会话会跟着走 |
| `pendingAsk` / `pendingPlan` | store 顶层 | 一个时刻只能悬一张卡 |
| `inflight` / `inflightDone` | **模块级单例** | 同一时刻只可能有一轮，`stop()` / `steer()` 分不清对象 |
| `skillIds` / `contextCourses` | store 顶层 | 是会话属性，却被当成全局 |

所以「放开那道闸」不等于「能切」：不解开单例，切过去会**两个循环往同一个视图写**。

## 二、核心设计：会话分桶 + 活动视图镜像

### 2.1 一句话

**「正在跑的一轮」属于它自己的会话；store 顶层那组字段永远只代表「当前正在看的那条会话」。**

- 每条会话有一份**会话视图**：`messages / loading / queued / pendingAsk / pendingPlan /
  planApplying / skillIds / contextCourses / loaded`；
- **活动会话**的这份视图就摊在 store 顶层（字段名与形状都不变）；
- **后台会话**的视图存在一个模块级 `parked: Map<number, SessionView>` 里；
- 切会话 = `park` 当前活动视图 + `restore` 目标视图（有缓存就**秒切**，没有才读库）。

顶层字段名、类型、语义全部保持 —— `CourseChat.tsx` 的三处取数、以及
`test-lazy-session.mjs` 那批直接读 `state().messages` 的单测都不用改。

### 2.2 写入口径：所有写入都过 `writeView(key, patch)`

```ts
type ViewKey = number | 0;              // 0 = 草稿态（activeId 为 null）

function readView(k: ViewKey): SessionView {
  if (k === activeKey()) return topLevelView(get());
  return parked.get(k) ?? EMPTY_VIEW;
}

function writeView(k: ViewKey, patch: Partial<SessionView>) {
  if (k === activeKey()) set(patch);            // 活动会话：老路径，行为不变
  else parked.set(k, { ...readView(k), ...patch });  // 后台会话：写进 Map，不触发无谓渲染
}
```

- `send` / `continueInterrupted` 里的每一次 `set((s) => ({ messages }))`、
  `patchAi`、`set({ loading })` 一律换成 `writeView(sessionId, …)`；
- 活动会话时 `writeView` 就是原来的 `set`，所以单会话路径**零行为变化**；
- 后台会话时只动 Map。用户在别处，不需要重渲染；切回来 `restore` 再从 Map 摊到顶层。

### 2.3 单例 → 按会话分桶

| 现在 | 改成 |
|---|---|
| `let inflight: InflightTurn \| null` | `const inflight = new Map<number, InflightTurn>()` |
| `let inflightDone / settleInflight` | `const inflightDone = new Map<number, Promise<void>>()` |
| `drainQueue()` | `drainQueue(sessionId)` —— 只捐自己这条会话的队 |
| `stop()` | 停 `activeKey()` 那一轮 |
| `steer(text)` | 作用于 `activeKey()` 那一轮；空闲则普通发送 |
| `releasePending(state)` | `releasePending(sessionId)` —— 只收自己这条会话悬着的卡 |
| `loading` 单布尔 | 顶层 `loading` = 活动会话的；另加 `runningIds: number[]` 给 Recent 判禁用 |

`send` 增加**可选目标会话** `send(text, mode?, target?)`：不传 = 活动会话（UI 走这条），
后台会话的队列由 `drainQueue(sessionId)` 带着 `target` 调它。**清草稿只在目标是活动会话时做** ——
后台续发不能把用户在当前会话打了一半的字吃掉。

### 2.4 会话装载：缓存优先

`loadSession(id)`：

1. `id === activeId` → 直接返回（幂等）；
2. `park` 当前活动视图；若 `parked` 里有 `id` → `restore`，**不读库**、秒切；
3. 没有缓存 → 先把顶层置成「读取中」（`loaded: false` + 空视图），读库；
4. 读库期间用户又切走 → 结果写进 `parked[id]`，不覆盖当前视图。

缓存优先是安全的：`chats` 表里 `LIBRARY_ASSISTANT_ID` 那批行**只有这个 store 在写**
（播放页面板写的是各自 `videoId` 的会话，命名空间不同）。它同时消掉了切会话时那一帧骨架闪。

## 三、守卫怎么放开（逐处）

| 位置 | 现在 | 改成 |
|---|---|---|
| `loadSession` | `if (loading) return` | 去掉 |
| `createSession` | `if (loading) return` | 去掉（切草稿态同样允许） |
| `deleteSessionById` | 按全局 `loading` 拦 | 只拦**目标会话在跑**（删正在流的那条会让循环往已删会话写行） |
| `setArchived` | 按全局 `loading` 拦 | 只拦**目标会话在跑** |
| `forkSession` | 按全局 `loading` 拦 | 只拦**目标会话在跑**（分支要读库，库里缺正在流的那条） |
| Recent `onClick` | `if (!loading) loadSession(id)` | 直接 `loadSession(id)` |
| Recent 行尾 分支/归档/删除 | `isDisabled: loading` | `isDisabled: runningIds.includes(id)` |
| Recent `deleteDisabled` | `loading` | `runningIds.includes(id)` |

放开后：**别的会话在跑，不影响你归档/分支/删除当前这条空闲会话**；只有「针对正在跑的那条」
才拦 —— 因为那会读写它还没落库的一截。

## 四、行为对照（实现后）

| 场景 | 结果 |
|---|---|
| A 生成中 → 点 Recent 里的 B | 立刻切到 B（有缓存秒切，没有读一次库） |
| 在 B 里提问 | 可打可发，B 起自己的一轮；A 不受影响，继续流 |
| 从 B 切回 A | 看到 A 仍在流式的回答（圆点在，停止键在） |
| A 答完 | 照常落库；B 那边无感 |
| A 里排了队，切到 B | B 的队列条是空的（队列跟着 A 走）；切回 A 队列还在 |
| A 悬着提问卡，切到 B | B 照常能发；切回 A 卡片还在，答它即恢复 A 的循环 |
| A 正在跑，想删 B | 允许（B 空闲） |
| 想删正在跑的 A | 仍拦（删了循环会往不存在的会话写行） |

## 五、刻意不做 / 取舍

- **草稿仍是全局的**（`draft` 不进会话视图）：切会话时输入框里打了一半的字跟着走，
  与现状一致。做成「每会话一份草稿」是更大的改动，本轮不做。
- **不 limit 后台并发数**：同一用户手速下同时跑三条以上不现实；真要收口，
  后面的口子在 `inflight.size`，现在留白。
- **缓存不做失效**：单写者前提下 `parked` 就是真源。若将来有第二个写者，再加刷新口。
- **播放页问答面板不动**：它整块状态在组件里（`msgs` / `loading` 全是 `useState`），
  要一起做得先抽共享 hook，见「流式期间的输入」那份设计的非目标。
