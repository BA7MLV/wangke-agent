## 背景

`docs/plans/2026-10-15-数据加载骨架屏-design.md` 已经把骨架屏的**纪律**落地了：
延迟门控（`useSkeletonGate`，200ms）+ 最短停留（400ms）+ 与内容同形 + 交叉淡入
（`SkeletonReveal`），并接入了资料库 / 课程助手 / 学习页。那一轮同时修掉了一个真正的
bug ——「未加载」被当成「确实为空」（不变量 I1）。

本轮把同一套纪律扩展到**还没覆盖的数据加载入口**。范围（按用户选择）：

1. 播放页面板：字幕 / 弹幕 / 卡片 / 讨论；
2. 材料阅读：`MaterialReader` + Word / Markdown / HTML 正文（PDF 已有逐页占位）；
3. 播放页首载；
4. 设置-模型列表：**本轮不做** —— 并行的「模型列表缓存」会话正在改
   `components/settings/ModelsModule.tsx`，同目录并发写会冲突（见「未纳入」）。

## 口径（沿用上一轮，不新造）

**本机数据读回是亚毫秒级**（IndexedDB 复用连接 p50 0.1ms），所以在面板这种「本地小查询」
上**不是**加一屏骨架，而是：

- **修 I1**：把「未加载」从「确认为空」里分出来（新增 `loaded` 三态），空态只在
  `loaded && 真的为空` 时出现；
- **骨架照上，但交给闸门**：`SkeletonReveal` + `CueSkeleton`，快路径一个都不出，
  慢设备（主线程被长任务占住）才会看到；
- **真等待才无条件依赖骨架**：材料解析（OPFS 读 + pdfjs / docx-preview）与播放页首载
  确实可能 >200ms，这两处骨架是主力。

### 不变量（新增/沿用）

| 编号 | 不变量 | 破坏它的后果 |
| --- | --- | --- |
| **I1** | 空态只在 `loaded && 确实为空` 时出现（沿用） | 「未加载」被当成「确实为空」 |
| **I2** | 加载在 `delayMs`（200ms）内结束 → 骨架一次都不出现（沿用） | 把不可感知的等待变成一次闪烁 |
| **I3** | 骨架一旦露出就至少待 `minVisibleMs`（400ms）（沿用） | 骨架闪一下被内容顶掉 |
| **I4** | 骨架几何与真内容对齐（沿用） | 加载完再抖一下 |
| **I8** | 骨架不冒用真内容的类名 / `data-testid`（沿用；本轮新增约束见下） | e2e 在骨架阶段误判「列表出来了」 |
| **I10** | 「上游数据是否就绪」必须是三态：`null`（未知）/ `true` / `false` | 用 `false` 兼表「未知」时，兄弟面板会先闪「请先生成字幕」 |

**I8 的延伸**：`panel.css` 里 `.sub-item` 是 e2e 的「列表出来了」判据
（`[role="tabpanel"]:visible .sub-item`）。所以面板骨架**不能**复用 `.sub-item` 类名，
只能把几何**分组进同一组选择器**（`.sub-item, .skel-cue__row { … }`）——
一处来源、不会漂，同时不冒用类名。

## 一、面板：`loaded` 三态 + 门控骨架

四个面板（`SubtitlePanel` / `DanmakuPanel` / `CardsPanel` / `CommentsSection`）的错形一致：

```tsx
// 改前（SubtitlePanel）
{segments.length === 0 && !running && <PanelPlaceholder>还没有字幕…</PanelPlaceholder>}
```

`segments` 由 `liveQuery` / `await db…` 写入，**首帧必然为空数组** → 有内容的课程会先闪一下
空态再被列表顶掉。改为：

```tsx
const [loaded, setLoaded] = useState(false);   // 切视频要复位
…
{loaded && segments.length === 0 && !running && <PanelPlaceholder>…</PanelPlaceholder>}
```

### 上游 `hasSubtitles` 也要三态（I10）

四个面板的「请先在字幕页生成字幕」占位靠 `hasSubtitles`。它在 `Player` 里是
`segments.length > 0 && !subsRunning`，而 `segments` 又来自 `SubtitlePanel` 的首个
`liveQuery` 回调 —— **首帧同样是 `false`**。于是兄弟面板会闪一下「请先生成字幕」，
和面板自己的空态闪是同一个病。

所以 `hasSubtitles` 改成 `boolean | null`（`null` = 字幕是否就绪还不知道），由
`SubtitlePanel` 的 `onLoadedChange` 通知 `Player`：

| 值 | 含义 | 面板渲染 |
| --- | --- | --- |
| `null` | 字幕状态未知 | 不渲染任何占位（骨架由闸门管），生成按钮禁用 |
| `true` | 有字幕 | 正常 |
| `false` | 确认没有字幕 | 「请先在字幕页生成字幕」 |

`isDisabled` 一律用 `hasSubtitles !== true`，`null` 与 `false` 都禁用（未知时不可点是对的）。

## 二、材料阅读

- `MaterialReader`：首载（OPFS 取文件）从 `<Spinner>正在打开材料…` 换成
  `<DocSkeleton variant="page|column">`，仍过闸门。
- `DocxReader` / `MdReader` / `HtmlReader`：正文渲染中（`!ready`）原本是
  `<Spinner>正在排版文档…`，换成同形文档骨架。
  - Word 是「白页卡片」（`.mr-docx … section.docx` 本来就是 `background:#fff`），
    骨架用 `variant="page"`：白卡 + 段条。
  - Markdown / HTML 是 760px 正文列，用 `variant="column"`：无卡片、居中列。
- `PdfReader`：**不新增整屏骨架** —— 它已经有逐页占位（`.mr-page__skel` 撑住每页的
  尺寸，页面进入渲染窗口才换成 canvas），这本身就是「同形」的渐进占位。
- 三个阅读器的页码槽 `<Shimmer text="载入中…" />` 换成 `<span className="skel-bar">`：
  它是**数值槽**，与学习页数字槽同一档（上一轮已定），Shimmer 文案是旧写法。

> 白页骨架的填充色：`.doc-skel--page` 的卡片恒为 `#fff`（与真实 docx 页一致），
> 所以里面的灰条用**固定浅灰**而不是 `--background-tertiary` —— 后者在深色下是深灰，
> 落在白卡上会变成「白纸上一条黑杠」（§五 那个坑的镜像）。

## 三、播放页首载

改前：`if (loading) return <div className="page player-loading"><Spinner/></div>` ——
连应用外壳都没有，整页空着等 `db.videos.get` + `getVideoFile`（可能 >200ms）。

改为渲染**同形骨架**：`PageShell`（保持顶栏 / 侧栏 / 返回键在位）+ `player-layout`
形状的骨架（左视频区 16:9 灰块 + 右面板栏）。仍然过闸门，快路径不留痕。

### 手法：怎么把「加载中」钉住（本轮新增两种）

1. **播放页**：跟上两轮一样钉 IndexedDB（`success`/`error` 永不派发）→ 播放页停在
   `loading` → 骨架稳定留台。
2. **材料阅读**：**只拖 OPFS 的 `materials` 目录读取 8 秒**（包一层 `getDirectoryHandle`），
   别的 IO 不动。整体钉 IDB 不行 —— 播放页要先读到 `videos` 那一行才知道这是材料，
   钉住就永远走不到阅读器。这一招把「骨架有结束条件」也一起验了：8 秒到点必须落到真内容。

### 顺带确认的既有取舍

- 面板读的是本地 IndexedDB（p50 0.1ms），**30× CPU 降速也不会越过 200ms 闸门** ——
  所以面板组没有「慢速路径出骨架」这条断言，「快速路径不出」才是它该守的方向。
  骨架本身的同形由 P 组量（播放页侧栏用的就是 `CueSkeleton`）。
