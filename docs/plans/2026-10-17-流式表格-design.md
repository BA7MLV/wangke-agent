# 流式表格：完整行渐进 → 长表折叠 → 手机 Bottom Sheet

- 状态：**已实现**
- 日期：2026-10-17
- 需求：把讨论里的表格方案落到现有 Markdown 渲染链路 —— 流式期间按**完整行**渐进出表、
  不出现可点的半成品；过长表格默认只露前几行，桌面点开展开、手机进 Bottom Sheet；
  UI / UX 用 HeroUI，动效参数接 `transitions.css` 的 transitions-dev 令牌。

---

## 0. 一句话方案

`MarkdownTable` 从外层 Provider 读「是否还在流式」：流式期只挂**单元格数与表头对齐**的完整行，
多列表最多露 6 行（单列全露）、列宽首帧定死、不放任何按钮；流结束后按行数 / 横溢判定折叠，
桌面内联展开，手机用 HeroUI Drawer 的 48dvh ↔ 92dvh 两档 Sheet，复制支持 Markdown 与 CSV。

## 2. 关键决策

### 2.1 流式状态用 Provider，不读 `streamStatus`

XMarkdown 的 `ComponentProps.streamStatus` 只对**自定义标签**有意义：
`detectUnclosedComponentTags` 扫的是 `components` 映射里的标签，而标准 `<table>` 在
HTML 里永远是闭合的 —— 流到一半时它照样是 `done`。

所以新增一个极薄的上下文，由 `Markdown` 包装器（课程助手）和 `ChatPanel`（播放页问答）
两处注入 `hasNextChunk`。题卡解析、材料阅读、历史消息没套 Provider，默认就是静态表。

### 2.2 只挂完整行：以「单元格数对齐表头」为准

XMarkdown 对表格有一个特殊放行：只要 pending 里有表头 + 分隔行 + 至少一行，就会把
半截表格也渲染出来。最后一行的单元格可能还没写完。反过来，这三样没齐之前它根本
不渲染表格 —— 所以「表头未完整」阶段不需要额外的骨架，空白比半张表更稳。

`MdTable` 只保留 `cells.length === 表头列数` 的数据行；流式期再把「所有单元格都是空白」
的行剔掉。于是：

- 行写了一半（少一格）→ 整行不出现，等 `|` 补齐再挂上；
- 行已经对齐但最后一个单元格还在长字 → 保留，文字自己增长（不会再换行）；
- 行列数对不齐的坏数据 → 不参与数值列判定，避免整表对齐被半行带偏。

### 2.3 多列流式期只露 6 行，结束后不「突然收起」；单列全露

需求原文是「流式阶段按完整行渐进画表；结束后超过阈值默认折叠」。如果流式期把 50 行全画出来，
结束那一刻再折回 6 行，用户正在读的内容会当面消失 —— 这是一次没有理由的布局跳变。

所以多列表格在流式期就按预览窗口画：前 6 行渐进出现，第 7 行开始出现一行**不可点**的
「正在生成更多行…」，流结束才换成「展开全部 · N 行」。这样：

- 半成品阶段没有任何可点入口；
- 长表从头到尾占据的高度一致，不会在收尾时塌一下；
- 50 行的表也不会在生成过程中吃掉整屏聊天。

单列表格是例外：它更像一列清单，折起来只剩 6 行反而更难读，所以流式与结束都全部露出，
也不出现「展开」入口（见 §2.5）。

### 2.4 列宽首帧冻结，结束再交回自动布局

流式期用 `table-layout: fixed` + `<colgroup>`，宽度由表头 + 首帧已经完整的前 3 行估算
（`columnWidthsPx`，CJK 按 2 个宽度计；每列至少 **64px**、长文本列封顶 **320px**）。
之后新行到来**不重算**。

用 px 而不是百分比，是因为百分比在窄屏上会把「时长」「进度」压到约 29px，
两个字只能竖排。px 下限 + 表格总宽下限（各列之和）才能保证表头不竖排；
宽度不够就让外层横向滚动，而不是把列挤扁。

这比「每来一行重新分配」更稳：列宽不会因为后面出现一个更宽的单元格而整体抖动。
流结束 `isStreaming` 变 false，colgroup 撤掉，回到自动布局重算一次最终宽度 ——
这一次重排是收尾，不是过程中反复抖。

### 2.5 折叠阈值：行数或横溢

`needsCollapse = 列数 > 1 && 数据行 > 6`；`isLong = needsCollapse || scrollWidth > clientWidth`。
单列表格刻意不折：它更像一列清单，折起来只剩 6 行反而更难读（需求里也明确不给
单列表展开入口）；空表 / 只有表头则根本没有工具行。
`table-layout: auto` 下表格变宽时容器尺寸不变，所以 `ResizeObserver` 同时观察容器与
`<table>`。流式期不做检测 —— 那时没有交互入口。

两种「长」的处理不一样：行数多才需要纵向折叠 / 展开按钮；纯横溢的表已经能横滚，
桌面端再点「展开」不会多出任何信息，所以只保留复制入口，不出现展开按钮
（手机端仍给「查看完整表格」，因为 Sheet 提供了更完整的阅读面）。

### 2.6 桌面内联，手机 Sheet

- **桌面**：默认 6 行，底部一条 `mask-image` 把最后一行淡出；点「展开全部」在气泡里
  拉高，超过 `62vh / 560px` 后内部滚动。没有引入 Modal：表格的上下文就在消息里，
  浮窗会把「读表」变成「离开对话」。
- **手机**：入口文案改成「查看完整表格」，点开 HeroUI `Drawer` 的 Bottom Sheet。
  两档 snap：半屏 `48dvh`、接近全屏 `92dvh`。拖手柄 32px 切档，向下拖过 120px 关闭；
  标题栏也有「展开 / 收起」按钮，键盘用户不用拖。
- Sheet 里放完整表（独立横向滚动），底部固定「Markdown / CSV」复制。HeroUI 负责
  遮罩、焦点陷阱、Esc、背景滚动锁；`onPointerDown` 在把手上 `stopPropagation`，
  否则 HeroUI Dialog 自己的拖拽关闭会把一次上拉同时解释成「关掉」。

### 2.7 复制：屏幕上是 React 树，复制时重建 Markdown

原始 Markdown 在渲染后已经拿不到，`markdownOf` 从 React 树里还原最常见的行内结构：
`**粗体**`、`*斜体*`、`` `代码` ``、`[文字](链接)`、`![alt](src)`、`~~删除线~~`。
不认识的标签退成纯文字，绝不把 HTML 塞进剪贴板。

`tableToMarkdown` 再统一转义：先反斜杠、再管道符、最后把换行换成 `<br>`。
顺序不能反，否则 `\|` 会被二次转义。CSV 走 RFC 4180：含逗号 / 引号 / 换行的格子加引号，
内部引号翻倍；行尾用 CRLF，Excel / Numbers / 粘贴都认。

### 2.8 动效只借 transitions-dev 的令牌

- 行入场：`--duration-fast` + `--ease-smooth-out`，只动 `opacity`。
  `<tr>` 上的 `transform` 在部分浏览器里不生效，稳比花哨重要。
- 展开箭头旋转、Sheet 高度切换、遮罩淡出都用同一套令牌。
- `prefers-reduced-motion: reduce` 下：行动画、进度点、箭头旋转、Sheet 高度过渡全关。

## 3. 坑

1. **别把 `streamStatus` 当表格流式信号**。标准 `<table>` 永远闭合，拿到的始终是 `done`。
2. **半截行必须按列数裁，不能按“最后一行”裁**。最后一行可能已经对齐、只是最后一个
   单元格还在长字；整行藏起来会让用户看到文字突然消失。按列数判断，对齐就留下。
3. **数值列判定要用完整行，不是预览行**。否则第 7 行一到、数值列集合变了，
   前 6 行的对齐会跟着跳一次。
4. **`<tr>` 上不要做 transform 动画**。部分浏览器对 table-row 的 transform 支持不稳定；
   只做 opacity。
5. **HeroUI `drawer__body` 自带 `margin: 8px -3px 0`**。不清掉的话表头比面板宽 6px，
   横向滚动时右边缘会被切掉。
6. **HeroUI 的 `drawer__close-trigger` 是 absolute `end-4 top-4`**，不占 flex 位置。
   标题栏必须自己留出 46px 右内边距，否则 snap 按钮会和关闭键叠在一起。
7. **Sheet 里的表格要允许 `pan-x pan-y`**。只写 `pan-x` 会把纵向手势锁死，
   半屏时用户没法在表格区域上下滚动。
8. **Drawer portal 在 `.x-markdown` 之外**。Sheet 里的表格必须自己套一层
   `x-markdown` 类，三线表 / 单元格内边距 / 数值列对齐才会继续成立。
9. **遮罩挂在 `<table>` 上，不挂滚动容器**。挂在容器上会把横向滚动条一起淡掉，
   宽表反而更难拖。

## 4. 验证

```bash
node scripts/test-markdown-table.mjs          # 10 条纯逻辑
BASE_URL=http://localhost:5199 node scripts/e2e-chat-table.mjs
npm run build
```

e2e 覆盖：

- 逐字符流：表中任何一行都不出现少列；流式期没有展开按钮；预览不超过 6 行；
- 流结束：6 行预览、展开 12 行、`aria-expanded` 翻转、收起；
- 复制 Markdown：剪贴板内容 = 表头 + 对齐分隔行 + 12 行，管道符 / 反斜杠转义；
- 手机：入口文案、Sheet 打开、12 行完整表、半屏 → 全屏、关闭；
- 短表不出现折叠入口；
- 单列表 8 行全部露出，不出现「展开」；
- 宽而短的表：桌面不出现「展开」（横向滚动已经够用），复制入口仍在；
- 手机流式：每列表头宽度 >= 60px，不被压成竖排；
- 页面无异常。
