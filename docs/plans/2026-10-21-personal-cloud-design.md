# 个人自部署云端版

状态：核心实现与本机验收完成；Docker 镜像／沙盒部署验收待 Docker daemon 可用。

## 背景与目标

首版为一套部署、一个管理员、多个登录设备。服务端保存课程原文件、全部学习表、模型凭据及任务。安装输出初始化 URL，网页完成账号、模型和 Passkey 配置。默认单文件 512 MiB。Agent 的命令、资料写入及联网权限默认不自动放行。

## 不变量

- 每个数据、文件、任务、凭据及审批请求均在服务端根据登录身份授权；客户端提供的 owner 不可信。
- 模型 Key 只写入服务器配置，读取配置仅返回已配置标记；普通聊天与 Bot 使用相同的服务端配置入口。
- 浏览器数据库是按账号隔离的缓存。修改与待同步记录必须在同一个 IndexedDB 事务提交；重试幂等，删除有墓碑；学习时长增量合并。
- 上传必须流式限流、计算校验并原子提交；不把 512 MiB 文件整块缓冲到 API 进程。
- 用户关闭网页不取消任务。显式停止才取消；审批绑定不可变的命令/参数，批准一次只执行一次；重启不盲目重复外部副作用。
- 旧本机数据保留，迁移必须明确选择并报告进度；退出登录不得继续展示该账号缓存。

## 设计

1. SQLite 记录仓库：白名单表、增量游标、字段级修改、幂等操作 ID。Blob 使用独立文件引用。客户端通过事务 outbox 推送并拉取增量，首次登录先完成同步再挂载应用。
2. 文件：账号下原文件及派生文件统一持久化，支持 Range 下载；备份覆盖全部权威数据。
3. 配置：账号配置保存供应商/模型/Agent 策略，凭据静态加密，配置 API 不回传明文；服务端模型转发仅允许配置过的端点。
4. 任务：持久化任务队列和事件。为复用现有 WebCodecs、PDF、DOCX、VAD 与生成流水线，首版采用服务器端 Chromium 任务执行器，执行器使用限定的内部身份，外部浏览器仅提交/订阅。它增加镜像与内存成本，换取现有功能一致性；后续可逐个替换为原生 Node 执行器。
5. Agent 权限：读取/写入/删除/命令执行/联网独立策略，默认写入与命令需要审批，网络默认禁用。服务端校验、审计，任务内再次检查权限。
6. 初始化：`/#/setup` 完成管理员初始化和服务配置；其他页面统一登录门禁。安装给出 URL 和一次性 secret 文件路径，支持公网 origin 参数。

## 涉及文件

- `apps/api/src/cloud/`：数据、文件、配置、任务与权限模块。
- `apps/api/src/server.ts`、`storage/database.ts`：认证接入及迁移。
- `src/cloud/`：启动门禁、同步、远程任务、服务器设置。
- `src/store/`、`src/pipelines/`、`src/harness/`：缓存与任务入口适配。
- `Dockerfile`、`compose*.yaml`、`install.sh`、`scripts/`：运行时、配置 URL 与备份。

## 验证

- API：身份隔离、批量事务、幂等重试、并发字段修改/删除、时长合并、大文件限制/Range、秘密不回传、审批拒绝/批准/撤销、任务重启。
- 两个独立浏览器上下文：初始化、登录、课程/聊天/学习记录同步、退出隔离、关闭提交端后任务完成。
- 现有 API/Bot/迁移测试与生产构建；必要的真实执行器端到端验证。
