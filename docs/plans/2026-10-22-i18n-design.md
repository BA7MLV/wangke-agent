# 界面国际化（i18n）规划

- 日期：2026-10-22
- 状态：**P0 已实现并验收**；P1～P3 待实施，未进行全站翻译。
- 已确认：首批支持简体中文（`zh-CN`）与英文（`en-US`），本轮落地首阶段，按模块迁移。

## 1. 调研基线（实施前）

本轮调研时项目尚无统一的应用级 i18n。已有多语言字幕，但那是学习内容能力，不是界面国际化；下表记录实施前的情况。

| 位置 | 当前情况 | 改造意义 |
| --- | --- | --- |
| `package.json` | 没有 i18next / react-i18next 等应用翻译依赖 | 需要建立资源、类型与切换机制 |
| `src/main.tsx` | 启动时同步主题，没有语言初始化或 locale Provider | 语言必须覆盖应用、登录门禁与初始化流程 |
| `src/store/settings.ts` | 有主题、字号等持久化设置，没有界面语言字段；槽位名等显示文案也在此定义 | 补充语言设置及旧数据兼容，避免 store 持有固定译文 |
| `src/components/SettingsModal.tsx` | 模块登记表直接保存中文 label | 改为保存翻译键，在渲染时求值 |
| `src/components/settings/AppearanceModule.tsx` | 中文文案硬编码 | 适合作为首个完整迁移模块与语言切换入口 |
| `src/pages/`、`src/components/`、`src/ui/` | 页面、空态、无障碍标签、确认框与通知分散保存文案 | 按完整用户流程逐批迁移 |
| `src/cloud/Gate.tsx`、`src/api/serverClient.ts` | 登录界面是中文；部分错误直接展示 API 错误码 | 登录前可切换语言，错误码映射到可读文案 |
| `src/cloud/preferences.ts`、`src/sync/units.ts` | 两条设置同步路径分别有字段清单 | 明确语言字段归属，不能只改 localStorage |
| `src/pages/Library.tsx` 等 | 日期有的跟随浏览器，排序有的固定 `zh-CN` | 统一显示格式与排序 locale，不改变存储格式 |
| `src/harness/prompts.ts` | 部分提示词明确要求“用中文回答” | AI 回答语言需独立规划，不能直接用界面 locale 替换 |
| `src/components/VoiceInput.tsx` | 浏览器语音识别读取 `document.documentElement.lang` | 更新页面 lang 前必须处理语音识别的隐式耦合 |
| `index.html`、`vite.config.ts`、`src/harness/widgetRuntime.ts` | HTML lang、标题、PWA 安装文案、widget 壳含中文默认值 | 区分可动态切换的界面元信息与安装后静态元信息 |

历史设计文档中的 MDUI 中文 locale 仅是当时的组件库本地化，不代表当前已有可切换的应用翻译体系。

## 2. 范围与不变量

### 首批要做

- 界面语言选择、持久化、中文回退、页面 `lang` / `dir` 与组件库 locale。
- 按阶段覆盖导航、设置、登录、聊天、课程库、播放器、学习页及其反馈与无障碍标签。
- 日期、数字、相对时间、显示用时长与文件大小、文本排序的统一入口。
- 翻译资源类型检查、完整性校验、中英文端到端回归。

### 不随界面语言改变

- 用户输入、文件名、课程名、导入材料、字幕原文、聊天记录与已有生成内容。
- AI 回答、讲义、卡片的生成语言；首轮维持原有策略，后续单独增加内容语言设置。
- 语音识别语种；不能因为用户切换英文界面，就把原本的中文识别改成英文识别。
- 路由、数据库主键、API 枚举、工具名、供应商/model ID、结构化生成协议。
- 学习时长的日期分桶、时区与时间戳。格式化只发生在显示层。
- 品牌名与专有名词不机械翻译；遵循项目现有品牌配置，不另建平行配置。

首批不承诺繁体中文、RTL 语种、文档全量翻译或安装脚本多语言；结构允许后续扩展。

## 3. 技术方案

### 3.1 翻译引擎与资源

采用 `i18next` + `react-i18next`，复用已有 Zustand 设置，不额外引入独立的语言持久化插件。

```text
src/i18n/
  index.ts                 # 引擎初始化与资源注册，不依赖业务 store
  locale.ts                # 纯函数：语言校验、系统语言匹配
  settings.ts              # 设置 -> 引擎 / HTML 的单向同步
  resources.ts             # 本地语言资源注册
  AppLocaleProvider.tsx    # React 翻译上下文与 HeroUI locale
  format.ts                # 后续：日期、数字、相对时间与 Collator
  errors.ts                # 后续：API 错误码到翻译键的映射
  i18next.d.ts              # 基于基准资源的类型声明
  locales/
    zh-CN/{common,settings}.json
    en-US/{common,settings}.json
    # 后续按模块增加 auth / chat / library / player / study / cloud
```

- 使用稳定、按语义命名的键；不以中文句子或数组下标作为键。
- 组件通过 `useTranslation(namespace)` 在渲染时翻译；非 React 调用在事件发生时调用翻译引擎。
- `MODULES`、主题选项、槽位显示名等配置保存翻译键，不在模块加载时缓存 `t()` 的结果。
- 整句插值，不把“已删除”+ 数量 +“条记录”拆开拼接；英文数量使用复数规则。
- 富文本按需使用 `Trans`，不通过不受信任的 HTML 注入翻译。
- 中文为回退语言。开发与测试暴露缺键，生产回退不能代替翻译完成度检查。

首阶段资源较少，随应用本地打包，不请求外部翻译服务。资源增长后再评估按语言/模块分包；若使用动态分包，加载成功后再提交语言切换，失败保留原语言。当前 PWA 已预缓存 JS，仍需实际验收语言资源离线可用性。

### 3.2 语言选择与兼容

建议增加 `uiLanguage: 'auto' | 'zh-CN' | 'en-US'`，区分“用户偏好”与“本机解析后的 locale”。

1. 显式选择优先；`auto` 按 `navigator.languages` 顺序匹配支持的语种。
2. 首批 `en-*` 匹配英文，`zh-*` 匹配简体中文；暂无对应译文的语言回退中文，不声称提供繁体翻译。
3. 建议新安装默认 `auto`；升级用户在旧设置迁移时明确保留 `zh-CN`，避免升级后突然变英文。
4. 未知值归一化到安全默认值；同时覆盖持久化合并、旧版迁移、设置更新、云偏好加载与旧同步导入。不能只校验 `update()`，因为现有云偏好使用 `setState()`。
5. 建议与主题一样作为账号偏好，接入个人云与旧同步的设置字段清单；同步保存 `auto` 而不是设备解析出的语言。
6. 登录前用本机偏好，登录后应用账号偏好；语言设置不依赖先登录才能访问。首阶段在登录门禁和外观设置都提供入口。
7. 监听系统语言变化仅对 `auto` 生效；显式选择不被浏览器偏好覆盖。

### 3.3 根部接入

- 在第一次 React 界面渲染前准备当前语言资源，启动错误也使用已初始化的翻译能力。
- `AppLocaleProvider` 挂在 `src/main.tsx` 的根部，而不是只包 `App`，使 `CloudGate`、初始化与登录页面同样生效。
- HeroUI v3 当前版本已导出 `I18nProvider`，与翻译引擎使用同一个解析后的 locale。Provider 只处理组件内部本地化，不会自动翻译业务文案。
- 更新 `<html lang>`、`dir` 和页面标题；不通过给应用设置语言相关 `key` 或刷新页面来切换，避免丢失草稿、播放位置、登录表单与进行中的对话。
- 对已有语音识别代码先解除与 HTML lang 的隐式绑定，首轮保留原有识别语种；独立语种选择后续设计。
- 引擎不反向 import `useSettings`，避免设置模块、错误提示与 i18n 之间形成循环依赖。

### 3.4 格式化、错误与历史数据

- 基于解析后的 locale 包装 `Intl.DateTimeFormat`、`Intl.NumberFormat`、`Intl.RelativeTimeFormat` 与 `Intl.Collator`；按 locale 和选项缓存实例。
- 不把播放器的机器可解析时间码、字幕时间轴或协议数字改为本地化字符串。
- 保留现有 API 稳定错误码，由客户端集中映射；未知错误提供通用提示并保留可复制的原始诊断信息。
- 非 React 的 toast / 确认框在触发时翻译。已排队的反馈可保留触发时语言，之后触发的反馈使用新语言；不重写持久化历史文本。
- 后台任务的中文 `message` 与结构化进度分别处理：后续以稳定的状态码和参数渲染界面，保留旧 message 兼容读取，不要求服务端加载 React 翻译上下文。
- widget 的产品控制壳可本地化，但生成内容与其声明的内容语言不能强制跟随界面语言。
- 动态页面标题与 PWA manifest 分开处理；已安装应用的名称通常不会即时随界面切换，不能以更新 `document.title` 宣称完成 PWA 安装元信息国际化。

## 4. 实施顺序

每个阶段单独验收，不在第一阶段宣称“全站英文已完成”。

| 阶段 | 主要工作 | 完成标准 |
| --- | --- | --- |
| P0：基础设施与试点 | 引擎、类型、语言偏好与兼容、根 Provider、语音解耦；完整迁移外观模块；登录前语言入口及语言控件本身的翻译 | 中英可切换、可刷新恢复、旧设置保留中文；不改变 ASR / AI 语言；不重挂载应用 |
| P1：公共交互与设置 | 导航、设置弹窗登记表、全部设置模块、登录初始化界面、共享反馈默认文案、认证错误映射与无障碍标签 | 从登录到配置模型的中英文流程可独立使用 |
| P2：主要学习流程 | 聊天及 composer/工具状态/附件、课程库及导入、播放器及字幕控制、学习页及错题组件、统一格式化与排序 | 中英文覆盖完整主要流程；输入、字幕与历史内容原样保留 |
| P3：云端与边缘入口收尾 | Bot、实时共享/访客、widget 控制壳、云任务进度与异常、导出模板标签、PWA 元信息策略；全量资源与回归检查 | 清楚列明保留原语言的内容；受支持界面无缺键、无漏迁的产品文案 |

AI 内容语言是单独的后续需求：决定默认跟随提问、跟随材料还是显式指定，并覆盖浏览器任务执行器与服务端生成路径。不要把全部中文 prompt 搬入界面翻译文件来代替该设计。

## 5. 验证与防回退

### 自动校验

- 增加 `scripts/test-i18n.mjs`：语言解析、非法输入、旧设置迁移、插值参数及语言资源校验。
- 增加 `scripts/check-i18n.mjs`：检查语义键覆盖、空值与占位符一致性；复数键按各语言规则归一化比较，不机械要求中文与英文原始键完全相同。
- 对已迁移模块检查遗漏的产品文案，逐步扩大范围；排除注释、测试夹具、用户内容、技能正文与 prompt，避免“一刀切禁中文”。
- 基于资源声明检查翻译键类型；随着阶段推进接入持续检查流程。

### 浏览器验收

- 无设置、升级设置、`auto`、显式语言、未知语言、系统语言变化、刷新与离线重开。
- 云模式：登录前可切换，登录后账号偏好应用，另一设备同步，`auto` 在两台设备分别解析。
- 语言切换不丢草稿、播放位置与进行中的请求；语音识别及 AI 内容语言没有隐式变化。
- 日期/数字/排序随 locale 改变，但存储值、日统计主键、字幕时间码不变。
- 英文单复数、长标签、空态、错误、tooltip、`aria-label` 与读屏文本。
- 桌面、窄屏及大字号下无截断关键按钮、遮挡或横向溢出。
- 现有中文 e2e 显式指定语言；流程定位优先用稳定 `data-testid`，另对真实翻译和无障碍名称做语言相关断言。
- 运行类型检查、生产构建及对应模块现有回归；本轮已执行的范围见下节，其余条目仍为后续验收计划。

## 6. 本轮落地结果

### 已实现

- 接入 `i18next` + `react-i18next`；中英文资源随应用打包，类型检查约束翻译键。
- 在 **设置 → 外观 → 界面语言 / Language** 提供跟随系统、简体中文、English 三项；登录/初始化页也可直接切换。
- 完整迁移外观模块（含阅读材料开关），并翻译设置入口、模块导航和关闭按钮；其他模块正文与登录表单正文仍保留中文。
- 根部同步翻译引擎、HeroUI locale、HTML `lang` / `dir` 与标题，不刷新、不重新挂载应用。
- 设置持久化版本升至 v5：新安装默认跟随系统，旧设置缺少语言字段时保留中文；设置更新、导入与云偏好加载校验非法值。
- 接入个人云偏好与旧同步白名单，保存 `auto` 偏好而非设备解析结果；账号没有语言偏好时采用登录前的选择。
- 浏览器语音识别保持原有 `zh-CN`，不再隐式读取界面语言；AI prompt 与用户内容未更改。
- 修正窄屏 Drawer 的默认负边距及英文大字号控件换行，避免设置面板横向溢出。
- 资源完整性检查接入 `npm run build`；单测与 e2e 登记到 `scripts/e2e-all.mjs`。
