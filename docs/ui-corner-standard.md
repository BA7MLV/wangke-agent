# UI 圆角规范

本规范记录 2026-10-30 用户确认的方向：参考 https://corne.rs/ 的柔和连续曲线，先统一语义圆角，再对主要卡片和弹窗选择性增强。语义 token、共享组件及主要页面已按此方向实施；实现覆盖、验证结果和已知限制见 `ui-radius-changes.md` 的「2026-10-30 语义规范化」章节，以下条款继续作为维护目标。

## 范围与原则

- 适用于 `apps/web` 应用界面；围绕现有 `theme.css`、HeroUI/Tailwind 映射及共享组件演进，不创建平行主题体系。
- 圆角服务于组件层级，不统一放大所有控件。优先从共享 token 和组件入口落实，再处理页面例外。
- 保持现有交互、布局及普通课程问答与 Bot 的界面定位。用户内容、独立作品、图表几何不作全局圆角覆盖。
- 以下 px 均按默认 16px 根字号换算，实际使用 rem，并兼容用户字号变化。

## 语义层级

- 基础档位：4 / 8 / 12 / 16 / 20 / 24 / 32px；无需让每个档位都成为公共组件 API。
- 微型元素：4px，例如复选框、代码片段底色、小缩略图细节。
- 紧凑控件：8px，例如紧凑按钮、菜单项、小型搜索入口。
- 标准控件：12px，例如常规按钮、输入框、选择框。`--radius-control` 默认指向此档位。
- 次级容器：12px，例如紧凑菜单、小型浮层。
- 标准面板/卡片：16px，`--radius-panel` 默认指向此档位。
- 弹窗和大面板：20–24px，`--radius-dialog` 默认 24px。20px 仅在比例需要时使用。
- 32px 仅保留明确需要的大型独立容器例外，不作为卡片、菜单或普通弹窗的通用默认值。
- 胶囊是形状语义：明确的徽章、状态标签和胶囊式分段控件可用 full；头像、圆形图标按钮等保持真正圆形。不得仅因组件原有默认全圆就把全部普通按钮当胶囊。
- 保留现有尺寸 token 兼容，新增/修改业务样式优先使用语义 token；同步 HeroUI 与 Tailwind 编译映射。

## 嵌套与贴边

- 内外同心可用 `max(0, 外圆角 - 内边距)` 作为起点，再按组件自身语义选择最接近的档位。
- 此公式仅用于真正沿边嵌套的表面，不强制作用于容器中所有按钮，也不为凑公式改变现有间距。
- 全屏/贴边面板、列表拼接边、气泡方向性与图片裁切保留其专用几何。单侧圆角按对应角分别处理。

## 连续曲率策略

- 默认采用原生 `border-radius`，小控件无需额外平滑。
- 大卡片和弹窗通过公共类、属性或公共组件明确选择平滑，不使用 `*`/全站伪元素通配增强。
- corne.rs 展示的 Lisse/Figma 曲线与 CSS `corner-shape` 的 superellipse 并不完全等价；禁止将某个 CSS 指数宣传成 Figma 的 60% smoothing。
- 若采用原生渐进增强，核验当前兼容性，使用 `@supports`，保留普通圆角回退；文档说明其为视觉近似。
- 仅在主要容器确实需要精确 Figma 曲线且验证收益后使用 Lisse，平滑度从约 0.6 开始视觉调校；查验当前官方 API 并封装复用，不逐元素分散接入。
- 平滑不能破坏阴影、边框、焦点环、滚动条、浮层定位或子菜单溢出。避免给有溢出内容的交互根节点直接施加裁切；需要裁切时分离装饰表面与交互内容。
- 圆形、胶囊、滑块、开关等不应用 squircle 增强。检查尺寸变化、响应式和现有动效，避免逐帧重算路径。

## 实施与验收要求

- 先审计 `theme.css`、`docs/ui-radius-changes.md`、`scripts/test-ui-radii.mjs` 和 `scripts/e2e-ui-radii.mjs`；保留已有合理工作，根据新规范更新与旧全局增强/旧数值绑定的断言。
- 当前工作区有其他会话未提交修改，必须先看 diff，做最小增量变更，不覆盖、重置或自动提交其他工作。
- 优先覆盖按钮/表单、卡片、菜单/选择浮层、设置弹窗与移动底部面板，并抽查课程聊天、Bot、资源库与侧栏。
- 使用桌面和手机视口、浅深主题做浏览器验收；检查嵌套边缘、边框与阴影、键盘焦点、弹层溢出、贴边形状、支持与不支持平滑的回退。
- 运行相关圆角回归、Web 类型检查及 `npm run build:web`。对既有失败与本次回归分别给出证据，不靠删除断言获得通过。
- 更新历史变更文档中的当前规则说明，保留历史清单的可追溯性；记录最终选择的平滑实现、覆盖面、例外及验证结果。
