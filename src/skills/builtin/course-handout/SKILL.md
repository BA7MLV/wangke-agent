# 对话内生成讲义

## 读取来源

1. 先确认本次范围。单课程使用 `/courses/current`；资料库助手使用当前会话的课程上下文。没有指定资料且无法从对话确定时，先询问，不自行挑课或拼接无关内容。
2. 复用 `read` 查看课程详情，取得真实正文路径、时长或页/段数；再用 `read` 分段读取正文，`grep` 补查术语、例题与重点。附件使用本轮实际提供的内容。
3. `read` 的范围用顶层 `start`、`end`；视频按秒，PDF 按页，其他材料按段。每次最多 600 秒或 20 页/段。全课讲义要覆盖全文，不能只搜几个关键词就声称已通读。
4. 长课程分章整理。工具或上下文预算不足时，先完成已读部分，明确已覆盖范围、未读范围与下一步起点，邀请用户继续，不编造剩余章节。

## Markdown 文件是唯一真相源

1. 课程讲义使用课程详情返回的 `/courses/{真实courseId}/handout.md`，单课程可用 `/courses/current/handout.md`。先 `read` 检查已有正文：该路径默认读取原始 Markdown，`offset` 从 0 起、`limit` 按行分页，不传秒/页范围。不要凭聊天历史重建文件。
2. 不存在时用 `edit(path=上述路径, create=true, content=Markdown正文)` 创建。应用会将普通 Markdown 资料保存到来源课程所在资料文件夹，名称为「课程名 · 讲义.md」；不新建讲义专用数据库正文，也不是写到用户电脑的宿主目录。
3. 已存在时重新读取相关段落，用同一路径的 `edit` 精确替换或按相邻正文追加。保留用户笔记、已完成章节和未要求改动的内容；不要新建「讲义2」「最终版」，也不要用聊天里的旧版覆盖文件。重名课程的路径以真实 courseId 区分，不能按显示名称猜。
4. 分章生成时，每完成一章就保存进同一文件，并更新文件中的覆盖范围与待续起点。保存后 `read` 回读核对，获得成功回执才说已保存；失败时明确说明草稿尚未保存，不切换另一份隐蔽副本。
5. 只基于附件或多课程合编、没有唯一来源课程时，先确认文件名与归属；可复用根目录 `.md` 路径创建普通 Markdown。用户明确指定已有 Markdown 路径时，以那份文件为准，不另建默认讲义。

## 组织正文

- 生成普通 Markdown 讲义并通过现有 `edit` 保存，可在对话流式展示草稿；不输出 IR/JSON，不调用旧讲义流水线，不等待 DOCX、抽帧或排版任务。
- 开头给出准确标题、来源与覆盖范围，然后给出概述和章节提纲。
- 按课程逻辑展开：核心概念与定义 → 原理/方法/步骤 → 原文例题及推导 → 对比与易错点 → 复习清单。原文没有的环节可以省略，不凑模板。
- 保留原文术语、适用条件、公式与必要中间步骤。补充解释必须与原文事实分开；看不清或证据不足就说明。
- 每个关键结论、例题标注来源：视频用 `[mm:ss]`，材料用 `[第N页]` 或 `[第N段]`，位置必须来自工具结果。
- 适度使用列表、表格与公式，内容以可复习为目标，不把完整讲义压缩成几句摘要。用户指定章节或篇幅时以用户要求为准。

## 图片与图表

- 纯文字来源也可以生成讲义，不以视觉能力作为前置条件。
- 复用 `read` 的 `frames` / `images` 目录和返回的引用展示已有画面、原图；目录名称不是图像证据，不声称看过未提供的像素。
- 用户附带截图时以实际截图或读图模型的转述为依据；识别失败的部分明确标记，不凭字幕补成图中文字。需要更多细节可请用户截取当前画面或框选原图提问，沿用应用现有读图通道。
- 确需解释性图表时才加载现有「讲解配图」技能并复用 `show_widget`，不新增工具、不用生成图冒充原图。

## 交付与后续

在对话中提供本次正文或修改摘要，并原样附上工具返回的讲义文件链接，方便打开阅读、编辑和下载最新 Markdown。聊天正文与会话导出只是历史快照，不是第二份最新版；后续查看、续写、改写都先读取文件。除非用户明确说只要草稿，否则生成讲义包含保存 Markdown，不再让用户另行复制归档。不要声称已生成 Word/PDF。
