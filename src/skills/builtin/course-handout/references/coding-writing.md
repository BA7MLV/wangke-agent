# 编程与计算机类课程

适用于 Markdown 编程讲义；通用结构、来源与保存规则沿用主技能及 writing.md。

## 概念与 API

- 每个核心概念交代是什么、解决什么问题、何时使用，不强凑三句固定模板；说明限制与代价，避免只写“能提升性能”。
- API、函数、类、类型与参数名保留原文大小写，不翻译、不改写。版本、运行环境、参数含义和返回结果具体；原文未提供的版本或默认行为不编造，补充说明单独标识。
- 区分课程示例、伪代码与可运行代码；说明示例输入、预期输出及必要依赖。不把某个版本或演示环境的行为说成所有环境都保证的结论。

## 代码与命令

- 短调用用行内代码，例如 `splitIntoCues(segments, maxLen)`；需要理解控制流、数据结构、配置或关键实现时用带正确语言标记的 Markdown 代码块，不设“三行以内”的硬上限。
- 代码保留理解与复现所需的上下文，如变量来源、导入、关键分支和必要错误处理；省略无关样板时标明省略，不用省略号破坏声称可运行的代码。
- 命令、路径、参数、配置键原样转写，例如 `npm run build`；解释其作用和前提，不只写“执行构建命令”。原文存在风险或环境依赖时提示，不擅自执行真实业务操作。
- 截图仅在确有帮助且有真实原图引用时补充，不能作为提供关键代码的前置条件，不输出 figure/time IR，不依赖抽帧才能生成讲义。无法识别的代码明确标记，不凭字幕补齐后冒充转录。

## 对比与过程

- 方案、工具、API 的对比可用 Markdown 表格，按同一组维度比较用途、约束、代价和适用环境；没有真实对比维度时用段落或列表，不硬凑表格。
- 算法说明输入输出、关键状态、步骤和终止条件；复杂度结论给出规模定义与假设，课程未讲则不凭空补成原文内容。
- 示例：`splitIntoCues(segments, maxLen)` 接收字幕段数组与单条最大字数，返回展示用 cue 数组；超长句按标点再细分。参数与输出比“接受一些参数、返回处理后的结果”更可核查，但仍须有来源依据。
- 必要的执行轨迹与中间状态保留在正文；静态结构图或交互单步仅作会话辅助，不以组件替代文件内必须读懂的代码与解释。
