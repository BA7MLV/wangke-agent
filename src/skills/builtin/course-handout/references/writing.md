# Markdown 讲义通用写作准则

本规范服务普通 Markdown 讲义，不生成旧讲义 IR。来源读取、范围声明、文件保存与交付仍以课程讲义主技能为准。先读本篇，再按内容读取相关专题，不把全部学科规范一起加载。

## 写作流程

1. 定主旨：先确定本章要解决的问题或核心结论，用一句准确的话引出正文，不要求固定的 lead 块或字数。
2. 搭结构：按概念、原理、方法、例题、辨析等实际逻辑分节；每节集中一件事，简单内容不强拆层级。用户指定结构时优先遵守，不为凑模板补写原文没有的环节。
3. 行文：结论与依据相连，定义说明对象与边界，流程按动作展开；保留推理所需的条件、证据及中间步骤，不用讲授先后顺序代替知识逻辑。
4. 自检：核对来源、术语、数字、推导与覆盖范围，删掉空话和重复内容，再按主技能保存与回读。

## 语言与证据

- 默认准确、简洁、朴实、清楚，用书面语；不写“干货满满、超级好用、受益匪浅”等宣传或评价性表达。用户要求通俗解释时可以自然表达，不把庄重语体当作所有课程的硬模板。
- 术语、专名、数字、条件与课程原文一致，不自造术语、缩写或例证。含糊的“多种场景、效果更好”应改成有依据的具体场景与效果；来源未给的信息不为追求具体而编造。
- 直接讲内容，不用“本节将介绍、让我们一起来看看、通过学习你将掌握”等元叙述凑篇幅。避免“综上所述、众所周知、毋庸置疑”等无信息套话和空洞强调。
- 不机械堆叠“首先、随后、最后”、对称句、感叹号或 emoji；真正的步骤顺序应保留，必要的教学设问不因文风限制而删除。
- 原文事实、原文例题与补充解释分开标识。关键结论和例题标注主技能要求的真实时间、页或段来源；不确定处说明证据缺口，不暗改原文错误来冒充原话。

## Markdown 内容组织

- 开头写准确标题、来源与已覆盖范围，接着分别写 `## 核心要点` 和 `## 内容大纲`，再展开分章正文。要点是已读内容的关键结论、方法与条件；大纲是正文的章节层次，两者不能互相替代。续写时同步更新，待续章节明确标识。用户指定结构时优先遵守。
- 正文章节标题用有实义的短语，不反复使用“介绍、概述、总结”充当全部标题；层级连续，不以固定标题数量限制课程结构。
- 段落一段一事，尽量先表达主旨，再给依据或解释；不把一句话拆成多段凑篇幅，也不按屏幕行数截断论证。
- 并列要点用无序列表，有先后或依赖的步骤用有序列表，每项动作与条件明确；条目尽量不重复、不交叉。允许正常 Markdown 标记与列表编号，不使用 IR 字段或等待渲染器代编全部编号。
- 表格只承载真实数据、条件、参数或方案对照；叙述、证明和长答案不硬塞表格。列数与单元格长度以可读性为准，内容过宽时拆表或改列表，不因旧的“四列、十五字、每节一表”限制删信息。
- 公式、代码使用 Markdown 能表达的合适形式，必要步骤与解释保留在正文。易错点用简短提示段或引用块，明确风险与适用条件，不为配额省掉重要提醒。
- 原图仅在确有帮助且有真实引用时插入，靠近相关内容，图注准确简短；使用工具返回的 Markdown 图片语法 `![说明](#source-image/...)` 写入文件，而非聊天专用的 `[图@mm:ss]`、临时 blob URL 或“此处插图”占位。不强制每节配图，不生成 figure/time 等旧 IR 块。无图时保留文字与来源，不编造图片。会话图表或交互组件是否能进入保存文件及导出，不能凭聊天展示成功推断。
- 字体、字号、行距、页边距、自动目录和分页属于编辑器或导出器；模型不以 HTML/CSS 或空格模拟 GB/T 9704，不承诺已有 Word/PDF 产物。

## 交前检查

- 来源和覆盖范围是否准确？有没有把未读内容写成已经完成？
- 每个结论、数字、名称和例题是否可追溯？补充内容是否与原文区分？
- 条件、关键推导、可操作步骤是否齐全？有没有仅为精简删掉必要解释？
- 段落和条目是否重复、交叉或充满无信息套话？表格是否真正帮助对照？
- Markdown 结构、公式和代码是否完整？是否误混入旧 IR JSON、自动排版指令或虚构图片引用？
- 核心要点与内容大纲是否分别完整，且与实际已完成正文一致？所选原图引用是否已写入同一文件的相关段落，而非仅展示在聊天？
- 修改是否保留用户笔记和未要求改动的正文？保存与回读成功前，不宣称已交付最新版。
