# 课程库目录整理

课程库的分类是**给人看的导航**，不是数据库索引。整理的成败标准只有一个：用户打开课程库时，
能不能在两三秒内找到「我现在要学的那门课」。

## 一、先摸清现状，不许凭印象

1. `list_courses` —— 拿到全部课程的**真实 id**。分类方案里的每个 `courseId` 都必须来自这里。
   课程名往往是「2024年某某课（1-8讲）」这种带序号的形态，靠名字猜类别十有八九会错。
2. `list_folders` —— 现有分类与「未分类」的数量。已经有「数学」就别再造「数学基础」。
3. 课程少（< 15 门）时用 `get_course_details` 抽查几门名字不明确的，确认它到底是什么内容。

## 二、定分类主轴

**一套分类只能有一个主轴**，混用是这类整理最常见的失败：

| 主轴 | 例子 | 适合 |
|---|---|---|
| 学科 / 领域 | 数学、英语、法律、经济 | 通识学习、跨学科检索 |
| 考试 | 考公行测、考研政治、雅思 | 应试备考（用户有明确目标时优先选它） |
| 用途 | 期末冲刺、写作素材、面试准备 | 阶段性任务 |
| 载体 | 视频课 / PDF 讲义 / 教材 | 几乎不要用 —— 用户按载体找课程很少，按内容找才对 |

选轴的判断依据是**用户在提问时怎么描述自己要找的课**。不确定时选学科：它最通用，跨主轴时也最不别扭。

**数量控制在 3~8 个**。多于 8 个，每个分类都只剩两三门课，导航反而更费劲；少于 3 个则等于没整理。

## 三、逐门给归属，不要漏也不要重

- 每一门课**必须且只能**出现在一个分类里。方案卡会按「后一个分类覆盖前一个」执行，重了用户看到的归类会和你描述的不一样。
- 拿不准的课放进「待定 / 其他」，并**在 summary 里点名**说明为什么拿不准。不要为了凑满而硬塞。
- 实在分不出内容的（文件名是「未命名」之类），先 `get_course_details` 看它有没有正文；什么都没有就归「待定 / 其他」。

## 四、命名

- 用**用户会用的词**：「考研数学」而不是「数学类课程」；「行测」而不是「公务员考试行政职业能力测验」。
- 不超过 24 字，不带序号、不带「课程」「资料」这类冗余后缀。
- 与现有文件夹同名就沿用（`propose_folder_plan` 会自动并入同名文件夹，不会新建重复项）。

## 五、提交方案，等确认

调用 `propose_folder_plan`，把思路写进 `summary`：

- 说明主轴是什么、为什么选它；
- 点名拿不准的课程与你的处理方式；
- 提醒用户：执行后可以随时在课程库里手动改回来。

**工具返回「用户没有执行方案」时，课程库没有发生任何变化。** 不要在回答里说「已经帮你整理好了」——
用户会回课程库一看完全没变，这比不做还糟。正确做法是问他想怎么调整（换主轴？减少分类？只整理某几门？）。

## 六、整理完还要做的

执行成功后，用一两句话说明最终分成了几类、各类多少门，并指出**用户最可能要动的那一门**。
整理的收益是导航，而导航的价值要有人点出来才有意义。
